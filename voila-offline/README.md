# Веб-конструктор ETL-дагов на Voilà (офлайн-установка)

Тот же интерфейс, что запускался в ноутбуке через `launch()`, но как **веб-приложение**:
открыл ссылку — работаешь. Код-ячеек не видно (нельзя случайно удалить/сломать), файл
ноутбука на диске не меняется, у каждого свой сеанс.

Собрано под сервер **без интернета**, Python **3.10**, поверх уже установленного
JupyterLab. Версия: **Voilà 0.5.12**.

## Что внутри

```
voila-offline/
├── wheels/                      # Voilà + зависимости (.whl), для офлайн-установки
├── install.sh                   # установка Voilà в окружение Jupyter
├── etl-dagbuilder.service       # systemd-сервис (запуск веб-приложения)
├── apache-dagbuilder.conf.example  # опционально: отдать под доменом через Apache
└── README.md
```

Приложение открывает ноутбук `tools/dagbuilder_app.ipynb` (в репозитории).

## Доступ и DNS — коротко

DNS/сисадмины **не нужны** для базового варианта:

- **Прямой порт** (по умолчанию): `http://<сервер>:8083/` — как JupyterLab на 8081.
  Ничего ни у кого просить не надо.
- **Под существующим доменом** через твой Apache (`.../dagbuilder/`) — см.
  `apache-dagbuilder.conf.example`. Тоже без нового DNS.
- **Новый поддомен** (`dagbuilder.oms66.ru`) — только это требует заявки на DNS.

## Установка (перенос флешкой)

1. Скопируй папку `voila-offline/` на сервер (флешкой / через Jupyter Upload).
2. Поставь Voilà в окружение Jupyter (без интернета):

   ```bash
   cd voila-offline
   PYTHON=/opt/jupyter/bin/python bash install.sh
   ```

   Установятся только недостающие пакеты; уже стоящие в Jupyter не трогаются.

3. Подними сервис:

   ```bash
   sudo cp etl-dagbuilder.service /etc/systemd/system/
   sudo systemctl daemon-reload
   sudo systemctl enable --now etl-dagbuilder
   systemctl status etl-dagbuilder      # должно быть active (running)
   ```

4. Открой в браузере **http://<сервер>:8083/** — появится форма конструктора.

> Порт 8083 выбран как свободный (8080 прод, 8081 Jupyter, 8082 airflow-test).
> Поменять — в `etl-dagbuilder.service` (`--port=`) и перезапустить сервис.

## Как это встраивается в текущий процесс

- Сервис работает под пользователем `jupyter` из общего клона
  `/opt/jupyter/workdir/konkin/etl` — то есть даги/структуры/конфиги генерятся туда же,
  куда и раньше. Дальше выкатываешь их как обычно (`local/dev-push.sh` / деплой).
- `UMask=0002` в сервисе → сгенерированные файлы груп-записываемые (правятся и
  удаляются с dev-ПК под `devel`, если каталоги — setgid группы `etldev`).

## Обновление кода

Логика — в `tools/dag_builder.py` и `tools/dag_builder_ui.py`. После их обновления
(деплой/pull в клон) просто перезапусти сервис:

```bash
sudo systemctl restart etl-dagbuilder
```

Voilà берёт свежий код при следующем открытии страницы (новое ядро на сеанс).

## Ограничение

Voilà использует те же виджеты ipywidgets, поэтому «список, который и раскрывается по
клику, и фильтруется по вводу» — по-прежнему недоступно штатно. Если это важно —
это аргумент за полноценный веб-апп (Flask + JS), но там больше работы и офлайн-JS.

## Аутентификация

По умолчанию Voilà открыт всем, кто дотянется до порта (как JupyterLab во внутренней
сети). Если нужно ограничить — можно закрыть basic-auth на Apache или добавить токен;
скажи, если потребуется.
